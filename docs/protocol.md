# Протокол Space Dogfight v1

Транспорт — WebSocket (`/ws`). Керувальні повідомлення — JSON з полями `v` (версія, зараз `1`) і `type`.
Два «гарячі» повідомлення — `input` і `snapshot` — ідуть через кодек: бінарний (за замовчуванням) або
JSON (`join.codec = "json"`, для порівняння).

## JSON-повідомлення

| Напрям | type | Поля |
|---|---|---|
| C→S | `join` | `room` (`[a-z0-9-]{1,32}`), `name` (≤16), `codec?` (`binary` \| `json`) |
| C→S | `chat` | `text` (1–200) |
| C→S | `ping` | `t` (час клієнта, мс) |
| C→S | `leave` | — |
| C→S | `input` | `seq` (u32), `b` (кнопки 0–15) — лише з JSON-кодеком |
| S→C | `welcome` | `playerId`, `room`, `tickRate`, `codec` |
| S→C | `roster` | `players: [{ id, name, color }]` |
| S→C | `chat` | `from`, `playerId`, `text`, `t` |
| S→C | `pong` | `t` (те саме значення, що прийшло в ping) |
| S→C | `shutdown` | — (сервер перезапускається, далі закриття 1001) |
| S→C | `snapshot` | лише з JSON-кодеком: `tick`, `ack`, `entities`, `events` |

Коди закриття: 1001 — сервер зупиняється; 4000 — некоректне повідомлення; 4001 — не надіслано `join` за 5 с;
4002 — перевищено ліміт повідомлень; 4003 — кімната заповнена; 4004 — клієнт не встигає читати; 4005 — сервер заповнений.

## Бінарний формат

Усі числа **little-endian**. Квантування:

| Величина | Тип | Формула | Точність |
|---|---|---|---|
| позиція x, y | u16 | `round(v · 40)` | 0.025 px (арена 1600×900 → максимум 64000) |
| швидкість | i16 | `round(v · 16)` | 0.0625 px/s, діапазон ±2048 px/s |
| кут | u16 | `round(angle mod 2π / 2π · 65536)` | 0.0055° |

### Input (клієнт → сервер), 6 байтів

| Зсув | Тип | Поле |
|---|---|---|
| 0 | u8 | тип = 2 |
| 1 | u32 | seq |
| 5 | u8 | кнопки: 1 — ліворуч, 2 — праворуч, 4 — тяга, 8 — постріл |

### Snapshot (сервер → клієнт)

Заголовок, 13 байтів:

| Зсув | Тип | Поле |
|---|---|---|
| 0 | u8 | тип = 1 |
| 1 | u8 | версія протоколу = 1 |
| 2 | u32 | tick |
| 6 | u32 | ack — останній застосований `seq` **цього** клієнта |
| 10 | u16 | кількість сутностей |
| 12 | u8 | кількість подій |

Далі сутності. Кожна починається з `u8 kind` і `u16 id`:

| kind | Розмір | Поля після kind+id |
|---|---|---|
| 1 ship | 18 | u8 playerId, u16 x, u16 y, i16 vx, i16 vy, u16 angle, u8 hp, u8 flags (1 тяга, 2 щит, 4 швидкострільність, 8 наведення, 16 мертвий), u16 score |
| 2 bullet | 15 | u8 owner (playerId), u16 seq (молодші 16 біт input, що її випустив), u16 x, u16 y, i16 vx, i16 vy, u8 homing |
| 3 asteroid | 11 | u16 x, u16 y, u16 angle, u8 radius, u8 homing |
| 4 pickup | 8 | u16 x, u16 y, u8 effect (0 shield, 1 rapid, 2 homing) |

Потім події, по 8 байтів: `u8 type` (1 fired, 2 hit, 3 exploded, 4 pickup), `u8 sub` (kind для exploded/hit, effect
для pickup), `u16 x`, `u16 y`, `u8 playerId`, `u8 by`.

Декодер перевіряє тип і версію, межі буфера перед кожним читанням (`truncated`), відомість `kind`/`effect`/`event` і
відсутність зайвих байтів у кінці. Будь-яка помилка — `CodecError`, а не падіння.

Відомі обмеження: `id` займає 16 біт і після 65535 куль починається спочатку (клієнт зіставляє сутності лише між
сусідніми знімками, тож колізія практично неможлива); `seq` кулі — молодші 16 біт.
